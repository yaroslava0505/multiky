# Правила роботи з цим проєктом

Статичний сайт-каталог мультфільмів. Без фреймворків і без npm:
Python 3 для збірки, чистий Vanilla JS у браузері. Хостинг — GitHub Pages
з папки `/docs` гілки `main`.

## Головне правило: не редагувати `docs/`

`docs/` — це **результат збірки**. Команда `python3 build.py` видаляє папку
повністю і створює заново. Будь-які правки всередині `docs/` зникнуть при
наступній збірці.

Редагувати тільки вихідні файли:

| Файл | Що в ньому |
|---|---|
| `src/style.css` | уся візуальна частина: кольори, шрифти, сітка, картки, модалка |
| `src/index.html` | розмітка головної сторінки (фрагмент `<body>`, без `<head>`) |
| `src/app.js` | логіка: пошук, фільтри, обране, модальне вікно, випадковий мультик |
| `src/data.js` | контент: 42 мультфільми + теми, категорії, вікові групи, сервіси |
| `src/art/` | картинки: `hero.webp`, `<ключ теми>.webp`, `<id мультфільму>.webp` |
| `build.py` | генератор: збирає з `src/` 53 сторінки в `docs/` |

Після будь-яких змін:

```
python3 build.py
```

## Що не можна ламати

**1. Токени кольорів тем.** У `:root` визначені `--t-friend`, `--t-help`,
`--t-feel`, `--t-kind`, `--t-brave`, `--t-family`, `--t-self`, `--t-loss`.
На них зав'язані смужки карток, плашки тем і заглушки постерів.

**2. Сайт тільки світлий.** Темної теми немає навмисно: жодних
`@media (prefers-color-scheme: dark)` і `[data-theme]`. У `:root` стоїть
`color-scheme: light`.

**3. Селектори, за які чіпляється `app.js`.** Якщо перейменувати їх
у розмітці — перестануть працювати фільтри й модалка:

- класи: `.card`, `.card-open`, `.chip`, `.theme-btn`, `.fav`, `.tabs button`,
  `.poster`, `.pill`
- id: `#grid`, `#q`, `#count`, `#reset`, `#reset-empty`, `#empty`, `#selection`,
  `#f-age`, `#f-cat`, `#f-fmt`, `#f-theme`, `#random`, `#modal`, `#modal-body`,
  `#modal-close`, `#fav-count`
- атрибути-гачки: `data-open`, `data-fav`, `data-tab`, `aria-pressed`

**4. Заглушки постерів.** Картинки є лише для 6 назв із 42. Решта малюється
з першої літери назви на тлі кольору теми (`.poster::after`). Список наявних
файлів `build.py` підставляє в сторінку як `window.POSTERS`, щоб браузер
не робив запитів до відсутніх картинок. Нову картинку досить покласти
в `src/art/<id>.webp` і перезібрати.

**5. Структура даних.** Поля мультфільму в `src/data.js`: `id`, `title`,
`originalTitle`, `poster`, `year`, `country`, `age`, `ageMin`, `family`,
`format` (`short` / `series` / `full`), `duration`, `categories`, `themes`,
`description`, `value`, `question`, `service`, `watchLinks`.
`build.py` читає цей файл як єдине джерело — окремого `data.json` більше немає.

